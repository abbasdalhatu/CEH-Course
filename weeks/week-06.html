Key Concepts

System Hacking Methodology

  1. Cracking Passwords — attempts to obtain account credentials.
  2. Escalating Privileges — attempts to gain higher permissions.
  3. Executing Applications — running programs or tools on a system.
  4. Hiding Files — concealing files or activity from ordinary inspection.
  5. Covering Tracks — attempting to remove or alter logs and artifacts.
  6. Maintaining Access — using persistence mechanisms to survive logoff or restart.
Defensive perspective: These stages describe attacker objectives for recognition and risk analysis. The practical exercises on this page focus on detection and controls, not carrying out unauthorized access, concealment, or persistence.

Password Cracking Methods

  • Dictionary Attack: Tests candidate words from a wordlist.
  • Brute Force Attack: Systematically tests possible character combinations.
  • Rainbow Tables: Uses precomputed lookup data against hashes that lack unique salts.
  • Hybrid Attack: Combines dictionary candidates with predictable variations.
  • Password Spraying: Tries a small number of common passwords across many accounts.
  • Credential Stuffing: Attempts to reuse credentials exposed in unrelated breaches.

Common Password Hashes

Hash / algorithmSecurity context
LM HashLegacy Windows format; obsolete and weak.
NTLM HashWindows authentication hash format; protect carefully and prefer modern authentication controls.
MD5Fast general-purpose hash; broken for collision resistance and unsuitable for password storage.
SHA-1Deprecated for collision-sensitive security uses; unsuitable for password storage.
SHA-256Modern general-purpose hash, but too fast to use alone for password storage.
SHA-512General-purpose hash; also too fast alone for password storage.
bcryptAdaptive password-hashing function designed to make guessing more expensive.

For new password storage, use a dedicated password-hashing scheme such as Argon2id, scrypt or bcrypt, with unique salts and parameters appropriate to the application.

Privilege Escalation Vectors

  • Unpatched operating-system vulnerabilities
  • Misconfigured services
  • Weak file permissions
  • Stored credentials
  • Kernel vulnerabilities
  • DLL search-order or hijacking weaknesses
  • Token and access-control misconfiguration
  • Insecure scheduled tasks
  • SUID/SGID binaries (Linux)

02 · Practical lab 6

Password Security & System Access Audit

Objectives

  • Understand how password hashes are stored and assessed.
  • Practice password auditing with synthetic training hashes.
  • Review account identity and permissions on a Linux test VM.
  • Identify privilege-escalation risk indicators safely.
  • Document findings and defensive recommendations.
Important lab boundary: The supplied course outline mentions the Metasploitable vsftpd 2.3.4 backdoor and password-hash extraction. This page does not provide steps to obtain a root shell or extract and crack real account credentials. You will instead document the known vulnerable service as a case study and complete safe, read-only checks on your own isolated VM.

Step-by-Step Instructions

Step 1: FTP Service Case Study (Metasploitable)

Metasploitable 2 is intentionally vulnerable and may include an old vsftpd 2.3.4 service. In this exercise, identify the service version only on your own isolated Metasploitable VM and document why unsupported FTP services are dangerous. Do not trigger the backdoor or attempt to obtain a shell.

# Confirm the target is your isolated Metasploitable VM.
# Read-only service-version identification:
nmap -sV -p 21 <LAB_TARGET_IP>

Record the detected service, version, evidence, potential impact, and recommended remediation (remove the vulnerable service, isolate the host, or rebuild from a trusted image).

Step 2: Understand Password Hash Storage

Study the roles of Linux account metadata and protected password-hash storage using documentation or instructor-provided sample files. Do not read, copy, export, or distribute /etc/shadow or another user's credential store.

# Display account names and metadata only (no password hashes):
cut -d: -f1,3,4,6,7 /etc/passwd

Step 3: Password Auditing with John the Ripper

Use only a synthetic hash file supplied by your instructor or generated specifically for this exercise. Do not use hashes obtained from real users or systems.

# Example workflow with instructor-provided synthetic test hashes:
john --wordlist=<APPROVED_TEST_WORDLIST> <SYNTHETIC_HASH_FILE>

# Display results for that synthetic test file:
john --show <SYNTHETIC_HASH_FILE>

Step 4: Understand Hashcat Modes

Hashcat supports different hash formats. The following are examples of mode identifiers for synthetic training data; only use the approved sample file and wordlist provided for the lab.

# MD5 example mode, synthetic training data only:
hashcat -m 0 -a 0 <SYNTHETIC_HASH_FILE> <APPROVED_TEST_WORDLIST>

# NTLM example mode, synthetic training data only:
hashcat -m 1000 -a 0 <SYNTHETIC_HASH_FILE> <APPROVED_TEST_WORDLIST>

Step 5: Review SSH and Account Security

Do not log in using recovered credentials. Review SSH configuration and account controls on a VM you administer, without changing settings during this exercise.

# Inspect SSH service status:
systemctl status ssh --no-pager

# Review effective account identity and groups:
whoami
id

Step 6: Linux Privilege-Escalation Risk Review

Use these read-only checks to understand the system's configuration. Do not run exploit code, change permissions, alter scheduled tasks, or attempt to elevate privileges.

# Kernel and OS information:
uname -r
cat /etc/os-release

# Review SUID/SGID file metadata (read-only):
find /usr/bin /usr/sbin -type f -perm /6000 -print 2>/dev/null

# Review cron directory metadata:
ls -ld /etc/cron.d /etc/cron.daily /etc/cron.hourly

# Review current account's sudo permissions:
sudo -l

Expected Outcomes

  • Documented service-version observation from the isolated lab.
  • Understanding of password hashes and safe offline auditing using synthetic data.
  • Read-only account and permission review.
  • Identification of privilege-escalation risk categories.
  • Professional technical report with evidence and defensive recommendations.

Assignment 6

Part A: System Hacking Documentation (60 points)

Complete a documented security assessment using your isolated Metasploitable VM and a Linux test VM you control. Do not trigger the vsftpd backdoor, extract real password hashes, or use recovered credentials to access a system.

  1. Identify the FTP service and version on the isolated Metasploitable VM and explain the security risk associated with the vulnerable version.
  2. Explain the difference between /etc/passwd account metadata and protected password-hash storage. Do not submit real credential data.
  3. Perform an offline password-auditing demonstration using an instructor-provided synthetic hash file with John the Ripper or Hashcat.
  4. Document account identity, groups, kernel version, selected file permissions, and current sudo permissions on your own Linux VM.
  5. Include screenshots and explain the defensive action recommended for each issue.

Part B: Privilege Escalation Research (40 points)

Research and explain these five Linux privilege-escalation techniques:

  1. Kernel exploits
  2. SUID/SGID binaries
  3. Writable configuration files
  4. Cron job misconfiguration
  5. sudo misconfigurations

For each technique, provide:

  • How it works (conceptual explanation)
  • How to identify the vulnerability safely
  • Potential impact if abused
  • How to prevent it
Submission Format: Detailed technical document with commands and screenshots from your own authorized lab. Include scope, methodology, findings, risk analysis, and remediation. Do not include passwords, private keys, real credential hashes, or instructions for exploiting systems outside your lab.
