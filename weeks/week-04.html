02 · Core concept

What is enumeration?

Enumeration is the structured process of collecting detailed information from services and systems that respond to authorized requests. It builds on network scanning: scanning may identify an open service, while enumeration helps determine what information that service makes available.

Information that may be exposed

  • Hostnames and device information.
  • Shared folders and access permissions.
  • Directory structure and group information.
  • Service configuration and software details.
  • Network time and infrastructure details.
  • Publicly available DNS and mail configuration.
Enumeration findings must be handled as potentially sensitive. Record only what is necessary for the assessment, avoid collecting personal or confidential data, and do not attempt to bypass access controls.
03 · Windows networking

NetBIOS and SMB enumeration

Server Message Block (SMB) is a network protocol commonly used for file and printer sharing. NetBIOS over TCP/IP is associated with legacy Windows networking and name services.

PortServicePurpose
137/UDPNetBIOS Name ServiceName registration and resolution.
138/UDPNetBIOS Datagram ServiceConnectionless datagram communication.
139/TCPNetBIOS Session ServiceSession-based communication, including legacy SMB.
445/TCPSMBDirect-hosted SMB file and printer sharing.

Defensive considerations

  • Disable SMBv1 where it is no longer required.
  • Restrict SMB access to trusted networks and authorized devices.
  • Require strong authentication and least-privilege share permissions.
  • Monitor unusual access to shared folders.
04 · Network management

SNMP enumeration

Simple Network Management Protocol (SNMP) helps administrators monitor and manage network devices. Depending on configuration, it can expose device names, interface information, uptime, and performance data.

VersionSecurity notes
SNMPv1Legacy version; community strings are transmitted without modern encryption.
SNMPv2cAdds protocol improvements but still relies on community strings.
SNMPv3Supports authentication and privacy protections when correctly configured.

Community strings are shared values used by older SNMP versions. Default or guessable values can expose management information. Avoid testing community strings against systems you do not own.

Defensive best practices

  • Prefer SNMPv3 with authentication and encryption.
  • Restrict management access using network ACLs.
  • Change default credentials and community strings.
  • Use read-only access wherever possible.
  • Monitor and log management queries.
05 · Directory services

LDAP enumeration

Lightweight Directory Access Protocol (LDAP) is used to access and manage directory information such as users, groups, devices, and organizational objects. Organizations often use directory services to support centralized identity and access management.

PortCommon use
389/TCPLDAP; encryption should be provided through StartTLS or a protected channel.
636/TCPLDAP over TLS (commonly called LDAPS).

Directory queries should be limited to approved accounts and attributes. Anonymous directory access should be disabled unless there is a documented business requirement.

06 · Mail services

SMTP, POP3, and IMAP

ProtocolCommon portPurpose
SMTP25, 587, 465Sending and relaying email.
POP3110, 995Retrieving email, with 995 commonly used for TLS-protected POP3.
IMAP143, 993Accessing and synchronizing mailbox contents, with 993 commonly used for TLS-protected IMAP.

Mail servers may publish configuration information through DNS and service banners. Modern servers should use encrypted connections, strong authentication, anti-relay controls, and appropriate logging.

Do not use VRFY, EXPN, or similar commands to harvest real user accounts. In this lesson, understand their purpose and the privacy risks they can create; use only a deliberately configured test service if a practical demonstration is required.
07 · File sharing and remote procedure calls

NFS and RPC

Network File System (NFS) allows systems to share directories over a network. Remote Procedure Call (RPC) enables a program to request a service from another system.

ServiceTypical portPurpose
NFS2049Network file sharing.
rpcbind / portmapper111Helps clients locate RPC services.

Defensive best practices

  • Export only required NFS directories.
  • Restrict NFS access to trusted hosts and networks.
  • Apply least-privilege permissions and appropriate identity mapping.
  • Disable unnecessary RPC services.
  • Monitor unexpected access to shared resources.
08 · DNS security

DNS zone transfers

A DNS zone transfer copies DNS zone information from an authoritative DNS server to another server, commonly to keep DNS infrastructure synchronized. An improperly restricted transfer can disclose a large amount of domain infrastructure information.

Zone transfers should be allowed only to explicitly authorized secondary DNS servers. Administrators should restrict transfer sources, monitor requests, and review DNS provider settings.

Important: Do not attempt AXFR requests against public or third-party domains without explicit written permission. For this lesson, inspect the concept using a local DNS server that you control or review a sample zone file.

10 · Practical lab 4

Service enumeration in an isolated lab

Objectives

  • Understand what service enumeration reveals.
  • Review SMB and service information on the lab target.
  • Explore SNMP and RPC concepts in a controlled environment.
  • Document findings without collecting unnecessary sensitive data.
Lab scope: Use only your own Metasploitable VM on a private host-only or dedicated isolated network. Confirm its IP address from the VM console. Do not connect the vulnerable VM to a bridged network or the public internet.
  1. Confirm the target address.

    On Kali, inspect the network interface and compare it with the address shown in your Metasploitable console:

    ip addr
  2. Review SMB service information.

    On your isolated lab target, use a non-authenticated share listing to see what the service intentionally exposes in this training VM:

    smbclient -L /// -N

    Do not open or copy files that contain personal or confidential information.

  3. Review SMB service identification.
    nmap -sV -p 139,445

    Record the service state and version information returned by the scan.

  4. Review RPC service information.
    rpcinfo -p

    Use the output to identify which RPC programs are advertised by the lab host.

  5. Document the remaining protocols.

    For SNMP, LDAP, NFS, and mail services, explain what information each protocol can expose and how an administrator should secure it. Do not attempt credential guessing, user harvesting, or access to private shares.

  6. Write a defensive summary.

    For every observed service, state whether it is required, who should be allowed to access it, and one control that would reduce unnecessary exposure.

Expected outcomes

  • SMB service information documented.
  • RPC service information documented where available.
  • SNMP, LDAP, mail, and NFS risks explained.
  • Defensive recommendations prepared.
