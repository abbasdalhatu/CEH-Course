02 · Core concept

What is ethical hacking?

An ethical hacker (or white-hat hacker) is a security professional who attempts to assess systems using techniques that may also be used by malicious hackers, but does so with permission from the system owner and for defensive purposes.

The defining difference is authorization and purpose. Technical ability alone does not make an activity ethical or lawful.

Types of hackers

  • White Hat: Works with authorization to identify weaknesses and help improve security.
  • Gray Hat: May act without clear authorization, even where the stated intention is not malicious. Unauthorized activity can still have legal consequences.
  • Black Hat: Uses hacking techniques for malicious, unauthorized, or criminal purposes.

04 · Methodology

The five phases of hacking

  1. Reconnaissance: Gathering information about a target, passively or actively, within the approved scope.
  2. Scanning: Discovering hosts, ports, and services in an authorized environment.
  3. Gaining Access: Validating whether a vulnerability can be exploited, only when explicitly permitted.
  4. Maintaining Access: Understanding persistence techniques as security risks and learning how defenders detect and prevent them.
  5. Covering Tracks: Studying attempts to manipulate or destroy evidence so defenders can recognize and protect logs. Never conceal activity during an authorized assessment; preserve evidence and report findings.
05 · Security foundations

Information security controls and attacks

Security controls are safeguards used to reduce risk and protect information systems. They are commonly discussed by their purpose:

  • Preventive controls: Aim to stop an incident before it occurs.
  • Detective controls: Help identify suspicious activity or policy violations.
  • Corrective controls: Help restore systems and reduce impact after an incident.

Creating a security baseline

A security baseline is a documented starting point describing the expected secure configuration of a system. It can include approved software, accounts and privileges, update status, firewall settings, logging, and network configuration. Comparing the current state against the baseline helps identify unwanted changes.

Information security attacks

Attacks may target confidentiality, integrity, or availability. Common vectors include compromised credentials, malicious software, vulnerable applications, misconfiguration, and social engineering. Understanding these risks helps organizations select appropriate controls.

07 · Practical lab 1

Setting up your hacking lab

Objectives

  • Install and configure VirtualBox or VMware.
  • Install Kali Linux in a virtual machine.
  • Install Metasploitable 2 as an intentionally vulnerable target.
  • Verify connectivity between the virtual machines.
  • Take baseline snapshots.
Isolation first: Configure both VMs on a private host-only network or a dedicated isolated virtual network. Do not use bridged networking for this vulnerable target. Do not expose Metasploitable to the internet, a campus network, or other networks containing devices that are not part of your lab.
  1. Install VirtualBox or VMware.

    Download the hypervisor from its official website, install it, and create or import a virtual machine.

    VirtualBox downloads

  2. Install Kali Linux.

    Download an official Kali virtual-machine image, import it, and configure its network adapter to use the isolated lab network.

    Official Kali virtual machines

  3. Install Metasploitable 2.

    Download Metasploitable 2, extract the VM files, import the virtual machine, and connect its network adapter to the same isolated lab network as Kali.

    Metasploitable 2 download

  4. Verify connectivity inside your isolated lab.

    Find the Metasploitable VM's IP address from its console. From Kali, test connectivity to that lab IP only:

    ip addr
ping <Metasploitable_Lab_IP>

    Only after confirming that the address belongs to your own isolated Metasploitable VM, you may identify its services for this exercise:

    nmap -sV <Metasploitable_Lab_IP>
  5. Take baseline snapshots.

    In your hypervisor, select each VM and create a snapshot named Baseline - Clean Install. This provides a known-good restore point.

Expected outcomes

  • Kali Linux VM running.
  • Metasploitable 2 VM running on the same isolated virtual network.
  • Connectivity between the two lab VMs confirmed.
  • Baseline snapshots created for both VMs.
