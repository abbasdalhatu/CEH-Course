02 · Core concept

What is network scanning?

Network scanning is the process of sending network requests to identify reachable hosts, accessible ports, and services. During an authorized security assessment, scan results help administrators understand which services are exposed and whether they match the organization's security baseline.

Common stages

  1. Host discovery: Determine which approved devices are reachable.
  2. Port discovery: Identify ports that respond to probes.
  3. Service identification: Determine which application or protocol is associated with a port.
  4. Version identification: Collect service-version information when permitted.
  5. Analysis: Compare findings with the approved baseline and document potential risks.
A scan result is an observation, not proof that a system is vulnerable. Validate findings carefully and avoid intrusive checks unless the written scope explicitly allows them.
03 · Networking foundations

TCP three-way handshake

TCP establishes a connection through a three-step exchange:

Client                         Server
  | -------- SYN -------------> |
  | <------ SYN + ACK --------- |
  | -------- ACK -------------> |
  |                             |
  |       Connection ready      |
  • SYN: The client requests to begin a connection.
  • SYN-ACK: The server acknowledges and responds with its own synchronization request.
  • ACK: The client acknowledges the response and the connection is established.

TCP and UDP

TCPUDP
Connection-oriented and uses acknowledgements and sequencing.Connectionless; does not establish a TCP-style session.
Commonly used by HTTPS, SSH, and email services.Commonly used by DNS queries, streaming, and real-time applications.
Connection behavior can provide useful information during port scanning.Responses may be absent, so interpreting scan results can be less straightforward.

05 · Interpreting results

Nmap port states

StateMeaningInterpretation
OpenAn application is accepting connections on the port.Identify the service and confirm whether it should be exposed.
ClosedThe host responds, but no application is listening on that port.The host is reachable; the port is not accepting connections.
FilteredA filtering device prevents Nmap from determining whether the port is open.Firewall rules or network filtering may be involved.
UnfilteredThe port is reachable, but Nmap cannot determine whether it is open or closed from that scan.Requires context from the scan method and network.
Open|FilteredNmap cannot distinguish an open port from a filtered one.Common in UDP scanning when no response is received.
Closed|FilteredNmap cannot distinguish a closed port from a filtered one.Interpret only in the context of the scan type.
06 · Tool fundamentals

Nmap command essentials

Nmap is a network exploration and security auditing tool. Use the following commands only with an authorized target. In this course, replace the placeholder with the IP address shown on your own isolated Metasploitable VM.

Target placeholder: <LAB_TARGET_IP> means the confirmed IP address of your own lab target. Do not copy a random IP address from the internet.

Basic discovery and scanning

# Check Nmap version
nmap --version

# Scan the default common TCP ports on your lab target
nmap <LAB_TARGET_IP>

# Discover hosts on your isolated lab subnet only
nmap -sn <YOUR_ISOLATED_LAB_SUBNET>

# Scan selected ports
nmap -p 22,80,443 <LAB_TARGET_IP>

# Identify services and versions
nmap -sV <LAB_TARGET_IP>

# Save normal output to a text file
nmap -oN lab-scan.txt <LAB_TARGET_IP>

Understanding scan options

OptionPurpose
-snHost discovery without a port scan.
-pSelects specific ports or a port range.
-sVAttempts to identify service versions.
-sTUses TCP connect scanning.
-sUPerforms UDP scanning; can be slower and needs careful interpretation.
-oNSaves output in normal text format.
-oXSaves output in XML format.
-oASaves output in multiple formats.

Do not use scan-fragmentation, decoys, source-port manipulation, or other evasion options to conceal scanning. This course focuses on transparent, authorized testing and accurate reporting.

07 · Practical lab 3

Network scanning with Nmap

Objectives

  • Confirm the IP address of your isolated lab target.
  • Perform a basic host and port scan.
  • Identify service names and versions.
  • Interpret Nmap port states.
  • Save and explain scan results.
Isolation check: Confirm that Kali and Metasploitable are connected to the same private host-only or dedicated isolated virtual network. Do not use bridged networking for the intentionally vulnerable target.
  1. Confirm the lab target address.

    Open the Metasploitable console and identify its IP address. In Kali, check the interface configuration:

    ip addr

    Make sure the target address belongs to your own lab VM before proceeding.

  2. Check reachability.
    ping <LAB_TARGET_IP>

    If there is no response, review the VM network adapters and firewall settings. Some hosts may block ping, so a failed ping alone does not prove the host is offline.

  3. Run a basic port scan.
    nmap <LAB_TARGET_IP>

    Record the port numbers, states, and service names that Nmap reports.

  4. Identify service versions.
    nmap -sV <LAB_TARGET_IP>

    Review the service information. Version detection can generate additional requests, so keep it limited to your isolated lab target.

  5. Save your results.
    nmap -sV -oA week3-lab-results <LAB_TARGET_IP>

    This saves results in normal, XML, and grepable formats. Keep the files with your lab report.

  6. Analyze and document.

    For each result, explain what the port is commonly used for, whether it should be available in the lab, and what defensive steps an administrator could consider.

Expected outcomes

  • Confirmed isolated lab target IP.
  • Basic Nmap scan completed against the lab VM.
  • Service and version observations documented.
  • Port states explained correctly.
  • Scan output saved for the assignment.
08 · Assessment

Assignment 3

Part B: Nmap lab report (50 points)

Using only your isolated Metasploitable lab target:

  1. Perform a basic Nmap scan and a service-version scan.
  2. Identify at least 10 observed ports if available; do not invent results if fewer are found.
  3. For each observed port, document its number, protocol, state, service name, and version if identified.
  4. Choose three services and describe one defensive best practice for each.
  5. Include the saved Nmap output and screenshots that show the lab target and isolated network.
Submission format: PDF report with screenshots, scan outputs, scope statement, and analysis. Use only your authorized isolated lab. Never include results from public or third-party systems.
